# 时间反死区

默认把摇杆输入强度从“输出幅度”改成“输出时间占比”：按本帧宿主映射曲线求值，曲线后强度低于游戏死区时，脉冲期间输出刚好让曲线后强度越过死区的输入幅度，其余时间归零；曲线后强度达到游戏死区后直接直通。这样宿主死区、灵敏度和曲线都参与计算，小幅输入也能越过下游死区；若下游只是把低于死区的值截断、不缩放，长期平均强度仍与宿主曲线后的强度一致。若下游会重新缩放死区以上的输入，可开启“缩放反死区”改用静态反死区映射。

## 原理

设输入强度为 `s`，宿主映射曲线为 `f`（含输入死区和灵敏度），游戏死区为 `m`（脉冲目标幅度），脉宽为 `p`，曲线后强度为 `t = f(s)`，反解出的脉冲输入幅度为 `a`，使 `f(a)` 刚好达到 `m`（连续曲线时 `f(a) = m`）：

```
占空比 = t / f(a)
周期   = p / 占空比 = p × f(a) / t
```

每个周期输出 `p` 毫秒的 `a` 幅度，其余时间归零，下游死区之前的平均强度为 `f(a) × (t / f(a)) = t`。

- `t = 0`：输入落在宿主自身死区内，不补偿。
- `0 < t < m`：按占空比 `t / f(a)` 脉冲输出。
- `t ≥ m`：曲线后强度已达到死区，直接直通。
- `t = m / 2`：宿主曲线为恒等映射时，脉宽等于等待间隔。

以恒等宿主曲线、`m = 20%`、`p = 4 ms` 为例：

| 输入 | 曲线后强度 | 占空比 | 输出 |
| --- | --- | --- | --- |
| 2% | 2% | 10% | 4 ms 输出 + 36 ms 等待 |
| 5% | 5% | 25% | 4 ms 输出 + 12 ms 等待 |
| 10% | 10% | 50% | 4 ms 输出 + 4 ms 等待 |
| 20% | 20% | 100% | 连续 20% |
| 30% | 30% | 100% | 直通 30% |

脉冲幅度按圆形归一化，即 `方向 × a`；宿主按增量叠加，插件返回的是与原位置的差值。

## 映射曲线

插件通过宿主提供的 `input.controls.sticks[id].curve(strength)` 读取当前绑定、当前帧的映射结果：把 `0..1` 的候选输入强度变换为含死区和灵敏度的 `0..1` 曲线后强度。脉冲模式下用二分反解出刚好越过游戏死区的输入幅度，缩放模式下同样按曲线反解，因此宿主的内置曲线、自定义曲线和灵敏度都会参与计算。

- 曲线按单调递增使用；非单调自定义曲线没有定义反解结果。
- `curve` 是协议量化前的值。实际输出仍会被下游量化，低幅度脉冲需要留余量，“游戏死区”建议略高于实际值。
- 输入落在宿主自身死区内时曲线后强度为 0，插件不会绕过宿主的输入死区。
- 旧宿主没有 `curve` 函数时回退为恒等映射，行为与旧版一致。

## 参数

三个参数都是绑定级（`scope: binding`），在摇杆属性页的“插件配置”里逐个映射调整；没有统一的启用开关，取消摇杆上的插件绑定即恢复直通。输入死区由宿主统一处理，本插件不再单独设置。

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| 脉宽 | 4 ms | 每次脉冲持续的时间；缩放反死区开启时不生效 |
| 游戏死区 | 20% | 宿主曲线后的游戏死区，脉冲模式下作为反解目标和直通阈值，建议略高于实际死区；缩放模式下作为下游死区 |
| 缩放反死区 | 关闭 | 开启后改用静态反死区映射，只使用游戏死区 |

## 缩放反死区

如果游戏不只是截断死区，而是把死区以上的输入重新缩放，例如 `(a - 死区) / (1 - 死区)`，时间脉冲模式无法让补偿区和直通区保持同一斜率。此时在摇杆属性页勾选“缩放反死区”，并把“游戏死区”填成游戏实际值（如 20%）。

开启后插件不再脉冲，而是把曲线后强度 `t` 静态重映射为游戏输入：

```
游戏输入 = 游戏死区 + t × (1 - 游戏死区)
```

再按宿主曲线反解出实际输入幅度。下游把 `游戏输入` 按 `(a - 死区) / (1 - 死区)` 缩放后得到 `t`，即宿主曲线后的强度，因此整个行程与宿主映射保持一致。该模式只使用“游戏死区”，脉冲宽度不生效。

开启后游戏看到的强度等于宿主曲线后的强度；相比游戏只应用自身死区缩放时，死区以上的输出也会抬高，整体灵敏度会变大，需要在游戏内适当降低灵敏度。

- 游戏死区填实际值或略小：估小会残留一点死区，但不会在中心产生漂移；估大会把中心附近的轻微抖动放大成输出。
- 如果游戏只是硬截断、不做缩放，保持本开关关闭，继续使用时间脉冲模式。

## 局限

- 输出粒度是一帧，无法输出半帧。脉冲宽度小于实际帧间隔时会被自动抬到一帧，否则低强度会被帧量化放大。
- 脉冲模式下“游戏死区”建议略高于实际死区，否则脉冲同样过不去；死区很低的游戏要把它调低。
- 上面的“平均强度不变”只对下游死区之前的幅度成立。很多游戏会把死区以上的输入重新缩放，例如 `(a - 死区) / (1 - 死区)`；此时脉冲幅度 `f(a)` 会被压成 `(f(a) - 死区) / (1 - 死区)`，补偿区与直通区的斜率不一致。开启“缩放反死区”并把“游戏死区”填成实际值即可消除这个差异。
- 插件只能按宿主曲线反解；游戏自身在死区之后的任意非线性曲线仍无法建模，“缩放反死区”也只对应 `(a - 死区) / (1 - 死区)` 这一种。
- 恒等宿主曲线、4 ms 脉宽、20% 游戏死区下：2% 曲线后强度约 4 ms 输出 + 36 ms 等待；5% 约 4 ms 输出 + 12 ms 等待。
- 下游若以 60 Hz 采样，短于约 17 ms 的脉冲可能被漏采，表现为偶尔一顿；长期平均值仍然正确。
- 宿主曲线必须是单调递增的；编辑器可以拖出的非单调曲线没有定义反解结果。
- 宿主曲线的最大输出仍低于“游戏死区”时无法补偿，插件按直通处理。
- `curve` 返回协议量化前的值；实际协议量化可能让低幅度脉冲落到死区以下，需要把“游戏死区”填得略高。

## 安装

把 `time_deadzone` 文件夹复制到 **EXE 同级的 `plugins/offline/`** 下，重启程序；也可以通过“从文件安装”选择本目录的 `manifest.yaml`。

然后在摇杆属性页的“附加插件”中选择“时间反死区 / 反死区摇杆”。配置示例：

```yaml
left_stick:
  plugin: {plugin: ecabea6e-4e13-4dd2-bc0d-9a5afc2ced14, id: stick}
```
